## Scope at the time

The founding plan for the product: a self-hostable, Google-authenticated
multi-tenant spaced-repetition backend plus a macOS menu-bar capture client. A
push-to-talk hotkey records audio, local Whisper transcribes it, a Claude-backed
LangGraph ingestion agent turns each transcript into `StudyEntry` rows, a fixed
1d/3d/7d/1mo/3mo/6mo schedule tracks reviews, and a nightly pre-generation job
builds MCQ quizzes for the next day's due entries so the client can speak a
digest and quiz at a time the user picks. It shipped as a **guided scaffold** —
17 implementation units (U1–U17) of typed stubs with teaching docstrings and a
test suite that fails against them.

## Decisions recorded only here

- **Decision-provenance convention.** The user's session-settled choices outrank
  any default the plan proposes; gaps are labelled *assumptions*, never
  decisions. No other doc carries this rule.
- **Stop condition.** Filling in the `NotImplementedError` bodies was the user's
  own follow-up learning work and explicitly **not** in the Definition of Done —
  nor were a live Google Cloud OAuth app or a deployed public demo.
- **Fixed-interval schedule is user-specified, not adaptive** — SM-2-style
  adaptive scheduling was deliberately deferred.
- **Push-to-talk hotkey over an always-on wake word** — avoids the battery/CPU
  cost and always-open-mic privacy exposure of continuous listening.
- **Local Whisper over a cloud STT API** — notes stay private, capture works
  offline, raw audio never leaves the machine.
- **The desktop client stays the capture and wake-up surface**, authenticating to
  the shared backend — a closed browser tab cannot speak the digest on schedule.
- **Quizzes pre-generated by a nightly batch, not on demand**, finishing inside
  the ~5–10 minute budget the user described, ahead of the earliest
  `preferred_review_time`; one in-process APScheduler, not a distributed queue.
- **Voice-quiz grading reuses the MCQ structured-answer contract** — the agent
  maps a spoken answer ("the second one", "B") to an option index, avoiding
  open-ended fuzzy matching; unrecognised answers re-prompt rather than guess.
- **Live-LLM verification is env-flag-gated and out of the default run** — those
  calls cost money and are non-deterministic; `pytest` on mocks is the spec.
  Pin LangChain/LangGraph versions, since unpinned installs would silently break
  the stub signatures the tests assume.
- **macOS-only desktop client (v1), documented not hidden.** `rumps`/`pynput`
  limit capture, wake-up and voice quiz to macOS; Windows/Linux users can still
  sign in, search history, and take web MCQs. Cross-platform is follow-up work.
- **Deferred scope:** SM-2 scheduling, always-on wake word, RBAC beyond
  `user`/`admin` (teacher / study-group sharing), hosted SaaS as primary, native
  mobile apps.
- **Per-user quiz sizing** — 10 questions × 4 options by default, configurable
  per user rather than globally.
